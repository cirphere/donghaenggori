# UI에 추가로 필요한 것 — 목업에 없는 화면

`prototype.html`(완성형 UI 목업)과 실제 서비스를 대조한 결과, **목업에는 없는데
우리 백엔드가 이미 하고 있는 것** 4가지다. 이대로 만들면 기능이 있는데 화면이
없어서 없는 것이 된다.

응답 모양의 전체 계약은 `docs/FRONTEND.md` 다. 이 문서는 **그중 목업이 빠뜨린
부분만** 따로 모은 것이다. 아래 응답 예시는 실제로 호출해서 확인한 값이다.

---

## 0. 먼저 — 직원용 API 는 전부 로그인이 필요하다

아래 엔드포인트를 그냥 부르면 **전부 401** 이다. `POST /api/auth/login` 으로 받은
토큰을 헤더에 실어야 한다.

```
POST /api/auth/login   { user_id, password }  →  { token, user }
GET  /api/auth/me                            →  현재 로그인한 사용자
POST /api/auth/logout

이후 모든 요청:  Authorization: Bearer <token>
```

- **`actor`·`role` 을 요청 본문에 넣지 않는다.** 서버가 토큰에서 신원을 꺼내
  쓴다. 보내도 무시되지만, 화면이 "김○○ 사회복지사" 를 적어 보내던 시절에는
  **화면이 말하는 사람과 감사 로그에 남는 사람이 달라졌다.**
- 토큰은 `sessionStorage` 에 둔다. `localStorage` 는 브라우저를 껐다 켜도 남고
  같은 오리진의 모든 탭이 공유해서, **복지관 공용 PC 에서 다음 사람이 앉으면
  그대로 로그인된 상태**가 된다.
- 401 은 화면마다 따로 처리하지 말고 한곳에서 받아 로그인으로 되돌린다.
  따로 처리하면 어떤 버튼은 로그인으로 가고 어떤 버튼은 빨간 글씨만 뜬다.
- **예외는 보호자 접수(`POST /api/guardian/intakes`) 하나뿐**이다. 이건 토큰
  없이 부르고, 응답에 대상자 프로필·이력이 들어 있지 않다(`GuardianIntakeOut`).

배선은 `frontend/public/api.js` 가 이미 하고 있으니 그 파일을 그대로 가져가면 된다.

## 1. 감사 로그 — 제일 급하다

`GET /api/audit?limit=100`  (토큰 필요)

```json
[{ "id": 12, "at": "2026-08-16 19:09", "actor": "김복지",
   "role": "사회복지사", "action": "확정",
   "target_type": "intake", "target_id": "3",
   "detail": "병원=고흥정형외과 / 방문일=2026-08-18 / 지원수준=휠체어·부축 동행" }]
```

`action` 은 여덟 가지다.

| action | 언제 |
|---|---|
| `확정` | 접수카드를 확정했다 |
| `미확인 확정` | **확인 필요가 남은 채로** 확정했다 (게이트를 사유 달고 통과) |
| `항목확인` | 통화로 확인한 값을 입력했다 (`detail` 이 `time=15:00` 형태) |
| `승인` / `거절` | 사후기록 초안을 프로필에 반영했다 / 안 했다 |
| `긴급전환` | 담당자 연결을 시도했다 (`actor` 가 시스템) |
| `긴급처리` | 사람이 긴급 건 연락을 끝냈다 |
| `이력추가` | 동행 완료 이력이 쌓였다 |

**왜 급한가.** 우리 서비스의 한 줄 주장이 *"AI는 후보·근거까지, 확정은 사람"* 인데,
그게 말이 아니라는 걸 보여주는 **유일한 물증**이 이 로그다. "그래서 누가 확정했는지
어떻게 압니까"에 답할 화면이 없으면 주장이 증명되지 않는다.

**표시할 때.** `미확인 확정` 은 다른 것과 섞이면 안 된다. 확인 없이 넘어간 건이라
눈에 띄어야 나중에 "누가 무엇을 확인하지 않고 확정했는가"에 답할 수 있다.

## 2. 확신 낮은 긴급 — 빨간 긴급과 구분해야 한다

`POST /api/intakes` 응답에 `urgent` 와 **`urgent_confident`** 가 함께 온다.
긴급이면 **`card` 가 `null`** 이므로 카드 대신 안내를 크게 띄워야 한다.

```json
{ "urgent": true, "urgent_confident": true, "card": null,
  "urgent_message": "긴급 신호 감지 — 접수카드 생성을 중단하고 즉시 담당자·사람
                     상담으로 연결합니다. 동행고리 AI는 응급 여부를 판단하지 않습니다." }
```

긴급 판정 임계값은 **놓치지 않는 쪽으로 낮게** 잡혀 있다. 그래서 인사말이나 STT
오인식처럼 **이해하지 못한 발화**도 사람에게 넘긴다. 그게 `urgent_confident: false` 다.

| | 동작 | 표시 |
|---|---|---|
| `urgent_confident: true` | 사람 연결 | **긴급** — 빨간 경보 |
| `urgent_confident: false` | 사람 연결 (같다) | **확인 필요** — 노란 배너 정도 |

동작은 같지만 표시가 같으면 안 된다. "고맙습니다 수고하세요" 가 빨간 긴급으로
뜨면 화면을 못 믿게 되고, 진짜 긴급이 묻힌다. `urgent_message` 문구도 그에 맞게
다르게 내려간다.

목업에는 긴급이 한 종류뿐이라, 모르고 만들면 두 경우가 합쳐진다.

## 3. 직접 접수 — 발화 입력 · 녹음 · 음성 파일

목업은 전화·문자로 **들어온 것을 받아보는** 화면만 있다. 복지사가 직접 넣는 경로가
빠졌는데, **시연 첫 장면이 그것**이라 없으면 데모가 시작되지 않는다.

세 가지 입력을 받는다.

```
POST /api/intakes                  { phone, utterance, channel, save }   (토큰 필요)
POST /api/stt                      multipart file  → 텍스트만
POST /api/intakes/from-audio       multipart file + ?phone=&channel=  → 접수카드까지
```

`channel` 은 `전화` / `앱·웹(보호자)` / `직접(기관)` 셋뿐이다.

`/api/stt` 응답:

```json
{ "text": "...", "confidence": -0.42, "needs_review": false,
  "language": "ko", "duration": 7.02, "model": "base" }
```

**`needs_review: true` 면 전사를 그대로 쓰지 말고 사람이 고치게 해야 한다.** 8kHz
전화 음질에서 확신도가 낮은 전사를 그대로 접수하면 병원명·날짜가 틀린 채로 넘어간다.

## 4. 사후기록 승인 — 저장과 반영은 다르다

목업은 사후기록을 **저장**까지만 있고 승인 단계가 없다. 우리 원칙 중 하나가
*"AI는 케어 프로필을 자동 변경하지 않는다"* 인데, 승인 없이 저장만 하면 그 말이
거짓이 된다.

```
POST /api/post-records                     → 초안 생성 (항상 '검토 필요')
POST /api/post-records/{id}/approve        { approved: true }
→ { "ok": true, "approved": true, "changed": true, "applied": true }
```

초안은 **제안**이다. 승인 버튼을 눌러야 어르신 프로필에 반영된다. 자동 저장 금지.

`changed: false` 는 이미 같은 상태였다는 뜻이라 **오류가 아니다**(더블클릭·재요청).
`applied` 로 프로필에 실제로 반영됐는지를 구분한다.

## 알아둘 것 — 목업 범위 밖에 이미 있는 화면

**보호자 웹** 은 별도 화면으로 이미 있다(`frontend/public/index.html`,
`guardian.js`). 보호자가 직접 병원동행을 신청하는 경로이고, `channel` 을
`앱·웹(보호자)` 로 보낸다 — `전화` 로 보내면 딸의 번호가 어르신 번호로 취급돼
"신규 대상자(미등록 번호)" 가 된다.

목업에 나오는 "보호자" 는 어르신 프로필의 연락처 필드일 뿐 이 화면이 아니다.
새로 만들 필요는 없지만, 복지사 콘솔만이 서비스 전부라고 오해하지 않도록 적어 둔다.

## 지금은 안 해도 되는 것

없어도 시연은 굴러간다. 나중에 붙이면 된다.

- **중복 재전화 표시** — 같은 번호가 10분 내 다시 걸면 합치지 않고 표시한다
- **대상자 후보 여러 명** — 보호자 번호 역조회 결과가 2명 이상일 때 고르는 UI
  (`card.target_candidates`). 목업은 항상 1명으로 확정된 상태만 그린다
- **복지시설·지역자원 조회** — `GET /api/facilities?region=&query=`
  (C-DS03·C-DS18). 목업의 "복지관" 은 기관명일 뿐 이 기능이 아니다
- **매니저 전달사항**(`card.manager_notes`) — 백엔드는 만드는데 목업에도 없고
  현재 `staff.js` 도 쓰지 않는다. **쓸지 버릴지 정하는 것이 먼저다**
