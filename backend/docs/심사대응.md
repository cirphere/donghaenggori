# 심사 예상 질문과 답

개념의 빈틈을 찌르는 질문 5개에 대한 답이다. 각 답은 **코드 어디에서 그렇게
동작하는지**까지 연결해 둔다. 말로만 준비하면 "그래서 지금 되나요"에서 막힌다.

시연 중 확인용 명령은 각 항목 끝에 붙였다.

---

## 1. 발신번호로 사람을 어떻게 확신합니까

남의 폰으로 걸 수도, 공중전화일 수도, 부부가 한 번호를 쓸 수도 있습니다.

**답: 확신하지 않습니다. 번호는 후보를 좁히는 단서일 뿐 본인확인 수단이 아닙니다.**

- 대상자에게는 항상 상태가 붙습니다 — `확인됨` / `추정` / `확인 필요`
  (`card.fields.target.status`). 번호가 일치해도 그 근거를 함께 내립니다:
  "발신번호가 등록된 케어 프로필과 일치 — 박순자"
- 보호자가 자기 폰으로 걸면 번호가 대상자와 다릅니다. 이때 **대상자를 확정하지
  않고** 보호자 연락처로 역조회해 후보만 제시합니다. 후보가 2명 이상이면
  `확인 필요`로 두고 확인 질문을 만듭니다 — "어머니이신 박순자 님 맞으실까요?
  성함과 생년을 확인 부탁드립니다."
- 미등록 번호는 `신규 대상자(미등록 번호)` 로 두고 임시 접수로 저장합니다.
  존재하지 않는 사람을 지어내지 않습니다.

관련 코드: `core/pipeline.py::_build_card` (대상자 상태·근거),
`core/db.py::find_by_guardian_phone` (보호자 역조회)

확인: 회귀 케이스 6·7 (`python -m tests.test_file3_cases`)

## 2. 접수 중에 "가슴이 아프다"가 나오면 어떻게 합니까

**답: 접수카드를 만들지 않고 즉시 사람에게 넘깁니다. AI는 응급 여부를 판단하지 않습니다.**

- 긴급 신호가 잡히면 카드 생성을 **중단**합니다(`card: null`). 접수를 마저 진행한
  뒤 알리는 게 아니라, 그 자리에서 흐름을 끊습니다.
- 규칙 사전에서 긴급이 잡히면 LLM 호출도 건너뜁니다 — 사람 연결까지의 시간이
  가장 중요하기 때문입니다.
- 놓치는 쪽을 최소화하도록 임계값을 맞췄습니다. 홀드아웃에서 **재현율 0.993**
  (실제 긴급 중 미탐 2건). 오탐이 늘어나는 건 감수합니다 — 긴급을 놓치는
  비용이 훨씬 큽니다.
- 다만 **긴급이라고 단정하지는 않습니다.** 임계값이 낮은 만큼 인사말이나 STT
  오인식도 걸립니다. 근거가 약하면(`urgent_confident: false`) 문구가 바뀝니다 —
  "발화를 명확히 이해하지 못했습니다. 접수카드를 만들지 않고 담당자 확인으로
  넘깁니다." 사람에게 넘기는 동작은 같고, 주장만 정직해집니다.

> **왜 규칙 사전만 쓰지 않았는가**: 규칙 사전만으로 재현율을 재보니 **0.098**
> 이었습니다. 열 건 중 아홉 건을 놓칩니다. 그래서 콜센터 상담 실데이터(C-DS01)로
> 분류기를 학습시켰습니다. 이 숫자는 심사에서 그대로 제시할 수 있습니다.

관련 코드: `core/pipeline.py::run` (긴급 분기), `core/classify.py` (임계값과 근거)

확인: 회귀 케이스 5, 시연 B-3

## 3. 전화도 못 거는 최취약 어르신은 어떻게 합니까

가장 도움이 필요한 사람이 가장 접수하기 어렵다는 지적입니다.

**답: 어르신이 직접 걸지 않아도 접수가 됩니다. 채널을 셋으로 나눴습니다.**

- `전화` / `앱·웹(보호자)` / `직접(기관)` — 생활지원사·사회복지사가 방문 중에
  대신 접수하는 경로가 처음부터 있습니다.
- 대리 접수는 예외 처리가 아니라 정규 흐름입니다. 보호자·기관이 요청하면
  대상자를 후보로만 제시하고 확인 질문을 붙입니다(1번 참조).
- 접수된 이력은 대상자에게 누적되므로, 다음 접수 때 병원 후보가 더 정확해집니다.
  대신 걸어준 한 번이 그 어르신의 기록으로 남습니다.

한계도 같이 말합니다: **발굴 자체는 이 서비스가 하지 못합니다.** 아무도 연락하지
않는 어르신을 찾아내는 것은 노인맞춤돌봄서비스 안부확인 등 기존 사업의 몫이고,
저희는 그 경로로 발견된 분의 병원동행 접수를 맡습니다.

관련 코드: `core/pipeline.py::CHANNELS`, `core/nlu.py::detect_proxy`

확인: 회귀 케이스 7, 시연 B-2'

## 4. 민감정보 동의와 녹취 근거는 있습니까

건강정보는 민감정보라 별도 동의가 필요합니다.

**답: 시연은 전부 가상 데이터이고, 실운영 전제 조건을 문서로 고정해 두었습니다.**

- 시연 데이터는 대상자·이력·장기요양등급까지 **전부 가상**입니다. 실제 개인정보가
  들어 있지 않습니다.
- 접수카드에 나가는 번호는 마스킹합니다 — `010-****-5678`.
- 모든 확정·수정·승인은 감사 로그에 남습니다(누가, 언제, 무엇을).
- 실운영 전제(현재 미구현, 도입 조건):
  최초 1회 본인·보호자 동의 · 통화 시작 시 녹취 고지 · 저장 시 비식별·암호화 ·
  보관 기간과 파기 절차. 이 조건이 갖춰지기 전에는 실제 개인정보를 넣지 않습니다.
- 음성 파일은 서버에 남기지 않습니다. 전사 후 임시 파일을 즉시 삭제합니다.

관련 코드: `core/card.py::mask_phone`, `core/db.py` (audit_log),
`web/api.py::transcribe` (임시 파일 삭제)

확인: 시연 마무리 단계의 감사 로그 3건

## 5. 누가 운영합니까. 서비스가 지속됩니까

**답: 독립 서비스가 아니라 기존 공공 전달체계에 얹는 도구로 설계했습니다.**

- 운영 주체는 지자체 복지관·읍면동 등 **이미 병원동행을 하고 있는 기관**입니다.
  새 조직을 만들지 않습니다.
- 이 도구가 대체하는 것은 사람이 아니라 **접수·기억·정리 업무**입니다.
  사회복지사가 더 많은 어르신을 보게 하는 것이 목표입니다.
- 등급 판정, 응급 판단, 병원 예약 확정은 하지 않습니다. 하지 않는 것을 코드에
  고정해 두었습니다 — 모든 응답에 `medical_judgement: false`,
  `human_review_required: true` 가 리터럴로 박혀 있어, 원칙을 바꾸려면 계약을
  깨야 합니다.
- 민간 서비스가 종료되면 데이터가 사라지는 문제를 피하려고, 저장소는 표준
  SQLite 파일 하나이고 공공데이터 외 외부 종속이 없습니다.

관련 코드: `web/api.py::Policy`

확인: `curl -s localhost:8000/api/intakes -X POST ... | jq .policy`

## 6. AI를 직접 만든 겁니까. 어르신 발화가 외부로 나갑니까

**답: 음성인식과 긴급 판단은 전량 자체 GPU에서 돕니다. 발화가 외부 LLM으로
나가지 않습니다.**

| 단계 | 어디서 도나 |
|---|---|
| 음성인식(STT) | 자체 GPU · faster-whisper |
| 긴급 분류 | 자체 GPU · KLUE-RoBERTa **직접 파인튜닝** |
| 날짜·병원·진료과 추출 | 자체 규칙 파서 |
| 시설 추천(RAG) | 자체 GPU · ko-sroberta 임베딩 |
| 필요도·접수카드 | 자체 코드 + SQLite |
| 통화망·음성합성(TTS) | ClawOps (외부) |

외부에 맡긴 것은 **전화를 걸고 받는 일과 안내 음성을 읽어주는 일**뿐입니다.
어르신이 말한 내용을 이해하고 판단하는 부분은 전부 우리 서버 안에서 끝납니다.

- 긴급 분류기는 기성 모델을 부른 것이 아니라 **직접 학습시켰습니다.** 규칙
  사전만 쓰면 재현율이 0.098인데, 학습한 모델은 **1.000**(미탐 0)입니다 —
  이 격차가 모델을 만든 이유입니다.
- 측정은 **AI-Hub 가 나눠 둔 공식 분할**로 합니다. TL 6,230 세션으로 학습하고
  VL 789 세션으로 평가했습니다. 정확도 0.997 · 긴급 재현율 1.000 · 정밀도 0.994.
  (예선 문서 목표: 정확도 85%, 재현율 97%)
- 다만 밝혀 둘 것이 둘 있습니다. **세션 도입부 5발화** 기준입니다 — 실사용이
  어르신의 짧은 첫 요청이라서입니다. 그리고 검증셋 고객 발화 129,029건 중
  **우리 4개 의도에 해당하는 49,678건**이 대상입니다. C-DS01 에는 우리가 다루지
  않는 상담 유형이 더 많습니다.
- 코드에 외부 LLM 보강 경로가 있지만 **키를 비워 꺼둡니다.** 켜져 있어도 긴급
  발화는 LLM을 타지 않게 막아 두었습니다(사람 연결까지의 시간이 우선).
- 녹음 파일은 서버에 남기지 않습니다. 전사 후 임시 파일을 즉시 지웁니다.

관련 코드: `services/stt.py`, `core/classify.py`, `core/nlu.py::analyze`

확인: 기동 로그 한 줄로 그 자리에서 보여줄 수 있습니다.

```
$ docker compose logs app | grep "AI 배치"
INFO: AI 배치 — 음성인식 medium(cuda) · 긴급분류 자체 모델 · 외부 LLM 미사용
```

> ⚠️ 이 답은 코드가 아니라 **`.env` 상태**에 달려 있습니다. `ANTHROPIC_API_KEY`
> 를 한 줄 채우면 외부 호출이 조용히 켜집니다. 시연 전에 위 로그로 확인하세요.

## 7. 시연 대본을 쓸 때 — 증상만 말하고 끝내지 않는다

**답(내부용): 목적지 한 단어를 붙이면 된다.**

긴급 분류기는 재현율 우선이라, 진료과나 '병원' 없이 증상만 말하면 긴급으로
기운다. 학습 데이터에 그 말투가 병원동행 쪽으로는 거의 없었기 때문이다
(합성 템플릿을 보강했지만 완전히 사라지지는 않았다).

```
다리가 저려서 그런디              → 긴급     0.996
다리가 저려서 병원 좀 가야 하는디     → 병원동행  0.001
귀가 잘 안 들려서                → 긴급     0.128
귀가 잘 안 들려서 이비인후과 가야     → 병원동행  0.001
```

긴급으로 잡히면 **접수카드가 만들어지지 않고** 담당자 호전환된다. 설계대로지만
시연에서는 보여줄 것이 사라진다.

리허설 전에 대본 문장을 그대로 돌려본다:

```bash
docker compose exec app python -c "
from donghaenggori.core import pipeline
문장 = ['여기에 대본을 한 줄씩']
for t in 문장:
    r = pipeline.run('010-1234-5678', t); c = r.card
    print(f'{t} → 긴급={r.urgent} 병원={c.hospital if c else None}')
"
```

심사에서 "긴급 아닌 걸 긴급이라 하면?" 이라고 물으면 이렇게 답한다 —
**"놓치는 비용이 훨씬 큽니다. 재현율 1.000을 택했고, 오탐은 담당자 연결로
흡수합니다. 공식 검증셋에서 정밀도도 0.994라 헛경보가 잦지는 않습니다."**
