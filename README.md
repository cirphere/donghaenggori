# 동행고리 AI — 예선 MVP

> 사회복지사를 위한 병원동행 접수·이력정리 Copilot
> 어르신의 짧고 모호한 전화 한 통("모레 정형외과 가야겄어")을, 사회복지사가 바로 확인·확정할 수 있는 **접수카드**로 바꾼다.
> **AI는 후보·근거만 제시하고, 최종 확정은 사람이 한다.**

## 무엇을 하나 (예선 데모 범위)

```
발화(전화/텍스트)
  → ① STT(텍스트 입력)
  → ② 케어 프로필 조회(발신번호)
  → ③ 발화 의도 분류(하이브리드 NLU: 규칙 + Claude)
  → ④ 병원 후보 생성(과거 이력 기반, 확인됨/추정/확인 필요 3단계)
  → ⑤ 동행 지원 수준 + 접수카드 생성
  → ⑥ 사회복지사 확인·확정 (사람의 영역)
```

긴급 신호("가슴이 아파")는 접수하지 않고 **즉시 사람/119 연결**로 전환한다(AI는 응급 여부를 판단하지 않음).

## 실행

```bash
cd app

# 1) 웹 대시보드 (추천 — 설치 불필요, 파이썬 표준 라이브러리만)
python3 webserver.py            #  → http://localhost:8765   (끄기: Ctrl+C)

# 2) 터미널 데모 (4개 시나리오)
python3 cli.py
python3 cli.py "010-1234-5678" "모레 정형외과 가야겄어"

# 3) (선택) Claude로 발화 이해 강화 — 없어도 규칙 기반으로 동작
export ANTHROPIC_API_KEY=sk-ant-...

# 4) (선택) Streamlit 버전 — pip 설치 필요
#    ※ Python 3.14에선 의존성(pandas 등) 설치가 불안정 → webserver.py 권장
pip install -r requirements.txt && streamlit run app.py
```

> **API 키 없이도 규칙 기반으로 데모가 돌아간다** — 발표 때 키 문제로 막힐 일이 없다.
> 키를 넣으면 사투리·모호 발화 해석이 Claude로 더 정확해진다.

## 구조

```
app/
  webserver.py   웹 대시보드 (표준 라이브러리만, 무설치) + SQLite(접수 기록·플라이휠)  ← 메인 데모
  app.py         Streamlit 대시보드 (선택, pip 설치 필요)
  cli.py         터미널 데모
  requirements.txt
  data/
    donghaenggori.db     (자동 생성) SQLite DB — 최초 실행 시 care_profiles.json으로 시드
    care_profiles.json   발신번호 → 케어 프로필 + 과거 동행 이력 (SQLite 시드, 합성 데이터)
    medical_terms.json   증상→진료과 / 진료과·긴급 키워드 사전 (규칙 NLU)
  donghaenggori/
    dateparse.py   상대 시간 표현('모레','다음주 화요일') → 날짜 (규칙, 결정적)
    nlu.py         하이브리드 NLU: 규칙 + Claude(키 있으면) — 의도·진료과·증상·긴급
    profile.py     발신번호 기반 케어 프로필 조회 (SQLite, 미등록=신규)
    hospital.py    과거 이력 기반 병원 후보 + 3단계 상태(확인됨/추정/확인 필요)
    needlevel.py   동행 지원 수준 후보 룰엔진(독거·거동·낙상·보호자)
    card.py        사회복지사용 접수카드 조립·렌더링
    pipeline.py    전체 오케스트레이션 (①~⑧, ⑨부터 사람)
    db.py          SQLite 데이터 계층(프로필·이력·접수 기록) + 플라이휠(이력 추가)
```

## 데이터 (SQLite) · 플라이휠

- 데이터는 **SQLite**(`donghaenggori.db`, 파이썬 표준 `sqlite3`, **설치 0**)에 저장된다. 최초 실행 시 `care_profiles.json`을 자동 시드한다.
- 테이블: `profiles`(대상자) · `history`(과거 동행 이력) · `intakes`(접수 기록·확정 결과).
- **★플라이휠** : 웹의 "🔁 동행 완료 → 이력에 추가"를 누르면 `history`에 한 건 쌓이고, **같은 어르신의 다음 접수에서 병원 후보가 추정 → 확인됨으로 올라간다**(쓸수록 똑똑해지는 학습 구조). 발표 핵심 장면.
- 심사 대비 한 줄: *"MVP는 SQLite(실현성·발표 안정성), 지자체 확산 시 PostgreSQL/클라우드로 교체. 표준 SQL이라 DB 중립."*

## 데모 시나리오 (검증됨)

| 입력 발화 | 결과 |
|---|---|
| "모레 정형외과 가야겄어" | 단골 → **🟢 확인됨** (○○정형외과, 근거: 6개월 2회 방문) |
| "저번에 무릎 봐준 데 또 가야" | 이력 해석 → 정형외과 확인됨 + 날짜 확인 질문 |
| "허리 아파서 정형외과" (010-2222-3333) | 🟡 추정 → **동행 완료 클릭 → 🟢 확인됨** (플라이휠) |
| "다음주 화요일 병원 가야" (신규) | **🔴 확인 필요** + 콜백 질문 생성 |
| "가슴이 아파서 숨이 차" | **🚨 긴급 → 접수 중단, 사람/119 연결** |

## AI 적용 (계획서 6장과 매핑)

| AI 기술 | 위치 | 비고 |
|---|---|---|
| 분류(LLM) + 규칙 | `nlu.py` | 발화 의도·진료과·증상 추출. 시간표현은 규칙 파서(`dateparse.py`)로 1차 처리 |
| 추론·생성 | `hospital.py` | 과거 이력으로 병원 후보 생성, **% 확신도 대신 결정적 3단계 상태** |
| 예측(우선순위) | `needlevel.py` | 동행 지원 수준 후보 |
| 요약·생성 | `card.py` | 접수카드(요약·근거·확인 질문) |
| 사람 확인 | `webserver.py` ③ | AI 자동화(①~⑧)와 사람 확정(⑨~⑩)을 구조적으로 분리 |

## 모델

- 발화 이해 LLM: **Claude `claude-opus-4-8`** (Anthropic SDK, `messages.parse` 구조화 출력).
- 키가 없으면 규칙 기반으로 동작 → **데모·발표는 키 없이도 가능**.

## 안전장치 (계획서 신뢰성·안전성 원칙)

- 병원명·진료과·응급 여부를 **AI가 확정하지 않음** — 후보·근거·"확인 필요"만 제시.
- 병원 후보 1차 근거는 외부 병원 DB가 아니라 **과거 동행 이력** → "별첨에 병원 데이터 없음" 약점 우회.
- 전화번호는 보조 식별 단서로만 사용(접수카드에 마스킹).
- 시연은 합성 데이터, 실제 개인정보 미사용.
