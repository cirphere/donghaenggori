## 한 문장

> **전화 한 통이 접수카드가 된다. 단, 확정은 사람이 한다.**

앞 절이 서비스이고 뒤 절이 차별점이다. **순서를 바꾸면 안 된다** — 서비스가
뭔지 모르는 사람에게 "AI 가 판단하지 않습니다"부터 말하면 미덕이 아니라
기능이 없는 것으로 들린다.

주제개요서가 `Good AI 관점의 신뢰성·설명가능성`을 평가 항목으로 못박아 두었다.
대부분의 팀이 "AI 가 다 해드립니다"로 갈 때 우리는 **AI 가 일부러 안 하는 것**을
보여주는 팀이고, 그게 이 트랙의 명시된 채점란과 정확히 맞는다.

## Day2 — 15분 (80점)

### 소개 2분 · 슬라이드 3장

| 장 | 내용 | 말할 것 |
|---|---|---|
| 1 | **장면** | "고흥군 어르신이 복지관에 전화를 겁니다." 실제 통화 음성 30초를 트는 게 최선. 배경 설명은 하지 않는다 |
| 2 | **서비스 정의** | "그 통화 하나가 이 카드가 됩니다." 접수카드 화면 한 장을 띄운다 |
| 3 | **약속** | "단, 확정은 사람이 합니다. 지금부터 8분 동안 그걸 보여드리겠습니다" |

배경(광주·전남 취약계층의 정보 접근성 문제)은 **주제개요서에 이미 적혀 있다.**
설명하면 아는 얘기를 되돌려주는 셈이고, 그 시간이 데모에서 빠진다.

### Demo 8분 — 슬라이드 없음, 실제 화면

| 장면 | 시간 | 겨냥 |
|---|---|---|
| 전화가 걸려오고 접수카드가 만들어진다 | 2분 | **실제 동작 여부** |
| **확정하려니 막힌다 → 통화로 확인 → 확정** | **2.5분** | **설명가능성·신뢰성 (하이라이트)** |
| 긴급 — AI 가 판정하지 않고 사람에게 넘긴다 | 1.5분 | 신뢰성·공공성 |
| 미등록 번호로 걸어도 접수된다 | 1분 | 접근성 |
| 사후기록이 다음 접수를 좋게 만든다 | 1분 | 데이터 활용 |

처음 보는 사람은 15분 중 **장면 하나만 기억하고 나간다.** 그게 말로 설명한
원칙이 아니라 눈으로 본 화면이어야 하고, 유일한 후보가 **확정이 막히는 장면**이다.
시간이 밀리면 다른 장면을 줄이고 여기를 지킨다.

### AI 기술 설명 2분 · 슬라이드 3장

| 장 | 주장 | 근거 |
|---|---|---|
| 1 | **어르신 발화가 기관 밖으로 나가지 않는다** | 외부 LLM 미사용. 음성인식·의도분류·검색 전부 자체 실행 |
| 2 | **직접 학습한 모델이다** | AI-Hub C-DS01 을 AI-Hub 가 나눠 둔 학습/검증 분할 그대로 사용. 정확도 0.997 · **긴급 재현율 1.000(놓친 건 0건)** · 정밀도 0.994 |
| 3 | **모델이 없어도 서비스가 죽지 않는다** | 3단 폴백 — 학습 모델 → TF-IDF → 규칙 사전 |

3장이 그냥 기술 자랑이 아니라 **"실제 동작 여부"** 항목에 직접 들어간다.
현장에서 모델 파일이 없거나 GPU 가 죽어도 접수는 계속 된다.

### Q&A 3분

`docs/심사대응.md` 7항목이 대본이다. **다만 그건 깊은 질문 대비고, 처음 보는
사람은 더 앞단을 묻는다.** 아래 셋을 반드시 준비한다.

| 질문 | 답의 뼈대 |
|---|---|
| "이거 지금 진짜 돌아가는 겁니까?" | 실제 전화번호로 걸립니다. 방금 데모가 그겁니다 |
| "어르신 통화 내용이 어디로 갑니까?" | 기관 밖으로 나가지 않습니다. 외부 API 를 쓰지 않습니다 |
| "스마트폰 없는 분은 어떻게 씁니까?" | **애초에 전화가 입구입니다.** 앱을 깔 필요가 없습니다 |

세 번째가 이 트랙의 `접근성` 항목을 정면으로 먹는 답이다.

## Day3 — 5분 (20점)

**데모를 본 사람에게 하는 이야기다.** 서비스 설명을 되풀이하면 5분이 날아간다.
첫 문장을 "어제 보신 화면이…"로 열어 연결한다.

### 핵심 성과 2분

- **실제로 전화가 걸린다** — 시연용 목업이 아니라 회선에 붙어 있다
- 자체 학습 모델: 정확도 0.997 · **긴급 재현율 1.000(미탐 0건)**
- 주최 측 제시 데이터 20종 중 **4종을 실제로 적재·사용**
  (C-DS01 학습 / C-DS03 광주 종합사회복지관 20건 · C-DS04 전남 노인복지시설
  30건 · C-DS18 광주 대기오염측정망 13건)

**개선폭이 아니라 절대 수준으로 말한다.** "예선 78.9% → 99.7%"는 앞 숫자를
모르는 사람에게 아무 의미가 없다.

### 사용자 가치 2분

| 대상 | 가치 |
|---|---|
| 사회복지사 | 무엇을 되물어야 하는지가 화면에 있다. 확인 전화의 반복이 줄어든다 |
| 어르신 | 헛걸음이 줄어든다 — 오전·오후를 잘못 잡으면 반나절을 버린다 |
| 기관 | **누가 무엇을 확인하고 확정했는지 남는다**(감사 로그). 책임 소재가 분명해진다 |

### 향후 고도화 1분

주최 측이 제시한 데이터 목록에서 **다음 단계를 지목한다** — 확산성 항목에 유리하다.

- **C-DS17 전남 사회복지시설(REST API)** — 실시간 연계로 확대
- **C-DS07 / C-DS11 위급상황 음성·음향** — 긴급 감지를 발화 내용에서 소리까지
- **C-DS16 고령인구 우울증** — 반복 통화 패턴에서 위험 신호 포착

## 하지 말 것

1. **배경 설명** — 주제개요서에 이미 있다
2. **예선 대비 개선폭** — 앞 숫자를 모르는 사람에겐 의미가 없다
3. **우리 용어를 설명 없이 쓰기** — *동행고리 · 접수카드 · 동행 매니저 ·
   확인 필요 · 동행 지원 수준* 전부 처음 듣는 말이다. 용어 슬라이드를 따로
   만들지 말고 **첫 등장에 한 마디씩 붙인다**: "접수카드 — 복지사가 보는 요약
   한 장입니다"
4. **Day3 에서 데모 재탕** — 같은 사람이 봤다
